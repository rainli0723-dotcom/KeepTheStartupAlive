# KTSA 产品介绍说明

Keep The Startup Alive｜AI 创业经营模拟沙盘与数字孪生团队平台

适用场景：产品说明、客户沟通、路演材料、内部培训、部署交付、To B 售前介绍。

## 1. 这是什么

KTSA，全称 Keep The Startup Alive，是一款面向创业团队、投资机构、孵化器、企业管理层和创业教育机构的 AI 商业模拟沙盘。

它把一家公司的组织档案、团队角色、商业场景、会议讨论、经营决策和复盘报告串成一个连续模拟系统。用户可以在真实商业代价发生之前，先用 AI 数字孪生团队预演融资、增长、竞争、组织、合规和危机等关键情境。

KTSA 不是一个普通聊天机器人，也不是只回答问题的 AI 助手。它更像一个可反复运行的经营训练场：用户输入公司背景，配置角色，启动模拟，然后在一轮又一轮商业事件中做决策、看结果、复盘原因。

## 2. 这是干嘛的

KTSA 的核心目标是帮助团队提前演练关键经营决策，降低盲目决策成本，提高团队共识质量。

它主要解决以下问题：

- 创业团队在融资、增长、定价、组织调整和危机处理前，缺少低成本预演环境。
- 团队会议常常受职位、情绪、信息差和表达习惯影响，很多真实分歧没有被充分讨论。
- 投资机构和孵化器需要更系统地观察创业团队的经营判断、风险意识和执行优先级。
- 企业培训和创业教育需要更接近真实经营压力的实战工具，而不是静态案例题。
- 复盘往往只停留在口头总结，缺少结构化记录、指标变化和后续行动建议。

KTSA 通过 AI 生成经营事件、组织多角色会议、输出决策方案、更新组织指标，并在模拟结束后生成复盘报告，让经营判断变成可以讨论、可以记录、可以比较、可以训练的过程。

## 3. 这是有什么用

### 3.1 提前暴露风险

系统会围绕现金流、增长动能、团队压力、技术风险、融资吸引力和生存概率等指标模拟企业状态。用户可以提前看到某个选择可能带来的连锁影响。

### 3.2 提高会议质量

数字孪生角色会从 CEO、CTO、CFO、COO、CLO、CMO、产品、销售、投资人、客户、监管方等不同视角提出观点。团队可以看到一个问题在不同职能眼里意味着什么。

### 3.3 训练经营判断

每一轮模拟都要求用户面对不完整信息做选择。系统会记录决策路径和结果变化，帮助用户理解短期收益、长期风险和资源配置之间的关系。

### 3.4 沉淀复盘资产

模拟结束后，系统可以生成会议纪要、复盘报告和最终结局报告，帮助团队把一次推演转化为后续战略讨论、培训材料或投资沟通材料。

### 3.5 支持 To B 交付

产品已经具备企业空间、成员权限、审计日志、健康检查、LLM 调用记录、报告导出、数据删除和生产 PostgreSQL 配置说明等 To B 产品化基础。

## 5. 产品核心模块

### 5.1 公司资料

用户可以创建和管理组织档案，包括公司名称、行业、产品、市场、发展阶段、收入情况、现金流、团队规模、治理结构和关键风险。

公司资料也支持导入文档或直接粘贴公司情况说明。导入内容会参与后续 AI 会议和复盘推演。

### 5.2 数字孪生

用户可以创建真实成员或虚拟角色，并配置角色名称、岗位、能力结构、个性、沟通风格和决策偏好。

系统内置完整角色库，包括创始人、CEO、CTO、CFO、COO、CLO、CMO、产品负责人、销售负责人、运营负责人、客户成功负责人、市场负责人、法务顾问、合规负责人、人力负责人、财务负责人、数据分析师、技术架构师、投资人、董事会成员、创业导师、行业专家、客户代表、供应商代表、合作伙伴、监管方、竞争对手观察员、区域负责人、事业部负责人、并购顾问、品牌负责人、政府关系负责人、国际化负责人和风控负责人。

### 5.3 场景库

系统内置融资、定价、市场竞争、组织、危机、增长、合规等商业场景，覆盖天使轮融资、A 轮融资谈判、融资失败应对、产品上线发布、竞品入侵市场、核心成员离职、监管政策收紧、增长停滞危机、IPO 上市准备和并购整合挑战等情境。

### 5.4 经营模拟

用户选择模拟模式、专项场景、参会角色和本局补充说明后，系统开始 20 轮经营模拟。

每一轮包括：

1. 生成经营事件。
2. 组织多角色会议。
3. 输出不同角色观点。
4. 生成决策方案。
5. 用户选择或补充判断。
6. 更新组织状态指标。

### 5.5 复盘报告

模拟过程中可以导出会议纪要。模拟结束后可以生成最终复盘报告，覆盖经营结果、关键驱动因素、决策路径、替代结局和下一步行动建议。

### 5.6 企业空间

企业空间用于管理账号、成员、权限、工作区、审计日志、LLM 调用日志和数据删除。它是产品走向 To B 售卖时的基础管理层。

## 6. 产品怎么用

### 第一步：配置环境

本地演示需要 Node.js 20+、npm 和一个可用的 LLM API Key。

```bash
npm install
cp .env.example .env
npm run db:push
npm run dev
```

打开：

```text
http://localhost:3000
```

### 第二步：配置公司资料

进入“公司资料”页面，填写公司基础信息，或上传公司资料文档。建议至少补充行业、产品、目标市场、收入情况、现金流、团队规模和关键风险。

### 第三步：配置数字孪生

进入“数字孪生”页面，查看系统内置角色，也可以新增真实成员或虚拟专家角色。对于关键角色，可以导入资料或 Skill，让角色更接近真实团队表达和判断方式。

### 第四步：开始模拟

进入“开始模拟”，选择场景模式或自由模式。场景模式适合明确训练目标，自由模式适合探索性推演。

### 第五步：完成模拟配置

在模拟配置页选择本局用户身份、默认角色、已创建数字孪生、公司情况和本局补充说明。

### 第六步：运行会议

系统会按轮生成经营事件和会议讨论。用户阅读角色观点，补充判断，选择决策方案，并观察组织指标变化。

### 第七步：导出和复盘

模拟过程中可以导出会议纪要。模拟结束后生成复盘报告，用于团队复盘、培训总结、投资沟通或客户交付。

## 7. 怎么配置

### 7.1 本地环境变量

```env
DATABASE_URL="file:./dev.db"
LLM_BASE_URL="https://api.deepseek.com/v1"
LLM_API_KEY="your-deepseek-api-key"
LLM_MODEL="deepseek-chat"
LLM_TIMEOUT_MS="60000"
LLM_MAX_RETRIES="2"
LLM_TEMPERATURE="0.4"
LLM_PROMPT_VERSION="v1"
```

如果网络需要代理：

```env
LLM_PROXY_URL="http://127.0.0.1:7897"
```

### 7.2 健康检查

访问：

```text
/api/health
```

健康检查会显示数据库连接、数据库类型、角色模板同步情况、工作区数量、LLM 是否配置和当前模型。

### 7.3 生产部署

正式 To B 部署不要使用本地 SQLite 数据库。生产环境应使用 PostgreSQL：

```env
DATABASE_URL="postgresql://ktsa_user:change-me@db.example.com:5432/ktsa?schema=public"
NODE_ENV="production"
LLM_BASE_URL="https://api.deepseek.com/v1"
LLM_API_KEY="your-production-llm-api-key"
LLM_MODEL="deepseek-chat"
LLM_TIMEOUT_MS="120000"
LLM_MAX_RETRIES="2"
LLM_WORKER_TOKEN="change-me-worker-token"
```

生产部署命令：

```bash
npm run prisma:generate:prod
npm run db:prod:migrate
npm run build
npm start
```

## 8. 一次标准演示流程

1. 打开首页，进入产品。
2. 在公司资料页导入或填写一家公司。
3. 在数字孪生页确认完整角色库。
4. 点击开始模拟。
5. 选择专项场景，例如融资、增长、竞争或危机。
6. 在模拟配置页选择参会角色。
7. 启动会议，让 AI 逐轮生成对话和判断。
8. 用户选择决策方案。
9. 查看组织指标变化。
10. 导出会议纪要或最终复盘报告。

## 9. 和普通 ChatGPT 的区别

| 对比项 | 普通 ChatGPT | KTSA |
|---|---|---|
| 使用方式 | 单次问答为主 | 连续经营沙盘 |
| 背景数据 | 用户临时输入 | 公司档案、角色库、场景、历史会议共同参与 |
| 角色能力 | 依赖提示词 | 数字孪生角色结构化配置 |
| 决策过程 | 结果难追踪 | 每轮事件、观点、方案、指标变化可记录 |
| 复盘能力 | 需要用户整理 | 自动生成会议纪要和复盘报告 |
| To B 能力 | 需要额外搭建 | 企业空间、权限、审计、健康检查、部署说明 |

## 10. 交付价值总结

KTSA 把创业经营中的不确定性转化为可模拟、可讨论、可衡量、可复盘的训练过程。

对创业团队，它是关键决策前的压力测试工具。

对投资机构，它是观察团队经营判断和风险意识的辅助工具。

对孵化器和教育机构，它是沉浸式商业实战训练平台。

对企业客户，它是新业务推演、组织训练和战略复盘的 AI 工作台。

一句话概括：KTSA 让团队在真实代价发生之前，先用 AI 数字孪生和经营沙盘把关键决策演练一遍。

## 11. 常见问题

### 没有公司资料或导入区怎么办

先访问 `/api/health`，确认数据库和工作区状态，然后刷新 `/organization`。

### 数字孪生角色不完整怎么办

刷新 `/team`。系统会自动补齐当前工作区缺失的默认角色。

### 开始模拟提示配置保存失败怎么办

查看页面错误详情，并访问 `/api/health`。常见原因包括数据库未初始化、没有工作区、权限不足或 LLM 配置错误。

### LLM 调用失败怎么办

检查 `LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、网络代理和 `LLM_TIMEOUT_MS`。如果模型返回格式异常，可以重试或切换兼容 OpenAI 格式的模型。

### 是否可以正式卖给企业

当前版本已经具备可演示和早期试点基础。正式 To B 售卖前，建议接入生产 PostgreSQL、完善部署环境、签署隐私政策和 DPA，并根据客户场景补充行业模板和样例报告。
